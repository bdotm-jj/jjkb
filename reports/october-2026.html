Key Findings & Recommendations

Current period (Apr 8 – Sep 11, 2026) vs Nov 2025 – Mar 2026 Baseline
  1. Testing volume is up sharply: 12 projects tested in the current period vs 8 in the baseline (+50%), with total tasks rising from 21 to 23.
  2. Retest efficiency improved: avg R2 round duration vs R1 deepened from -42.9% (baseline) to -58.0% (current) — i.e. second rounds are running shorter relative to R1 than they did in the baseline. This is a round-length trend, not a change in how many projects needed a second round.
  3. First rounds are taking longer: avg R1 duration rose from 5.25d to 6.08d (+15.9%), driven in part by the Workflow Dashboard outlier (20-day R1).
  4. Longest test cycle grew: Scottsdale API and Workflow Dashboard both closed at 21 days, up from RenRe's 16-day baseline high (+31%).
  5. Data gaps persist: 3 tasks with logged durations (JJCM – New MARS Claims System, CertifID, Munich RE – Commercial) have no Start Date and were excluded from both periods' calculations; 5 additional tasks have neither duration nor start date.

Recommendations

  1. Review Workflow Dashboard's 20-day R1 in a retro — if it's a one-off scope issue, exclude it from trend benchmarking; if systemic, revisit R1 effort estimates portfolio-wide.
  2. Ask project owners to backfill Start Date on the 3 duration-only rows so they can be included in future baseline/current comparisons.
  3. Continue monitoring the R2-vs-R1 duration trend — R2 rounds running shorter relative to R1 is a positive signal on retest efficiency worth highlighting in team retros.
